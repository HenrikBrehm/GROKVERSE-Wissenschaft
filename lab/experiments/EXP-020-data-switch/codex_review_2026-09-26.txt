# Codex Adversarial Review

Target: branch diff against HEAD~1
Verdict: needs-attention

No-ship. The tensor switch occurs after exactly t F updates and retained Adam state is documented, but the experiment does not identify a commitment time, and the analyzer can turn arbitrary/nonmonotone crossings into a 5/5 confirmation.

Findings:
- [high] Switch time is confounded with the amount of subsequent G training (lab/experiments/EXP-020-data-switch/README.md:31-40)
  Every run ends at step 2000, so increasing t simultaneously increases F exposure and reduces G exposure from 1950 to 1000 steps. Even a completely reversible learner can therefore retain F simply because G had less time to overwrite it. The resulting crossing estimates a finite-horizon F/G dose balance, not the time at which the frequency set became causally committed. Comparing that quantity with gen_F does not repair the confounding.
  Recommendation: Give every switch condition the same post-switch G budget, or continue G until a predefined convergence/stability criterion. Include matched G-only continuation and preferably reverse-switch controls before calling the crossing a commitment time.
- [high] The analyzer fabricates a point threshold and accepts non-threshold curves (lab/experiments/EXP-020-data-switch/analyze.py:63-101)
  d is a discrete top-5 count observed at only six settings, yet t_half assumes linearity in an arbitrary log(t+25) coordinate. More seriously, the first positive value is accepted even when later finite-grid values become negative: `monotone` is only reported, while `supports` still uses the early interpolated crossing. For example, d=[-1,1,-1,-1,-1,1] is valid by the endpoint rule and produces an early supporting t_half despite exhibiting no stable threshold. The subsequent sign test can therefore report 5/5 and p=1/32 from five analysis artifacts.
  Recommendation: Treat each crossing as interval-censored between grid points, require a pre-specified monotonic/stability rule, and classify H20 as support only when the entire threshold interval precedes the generalization bound. Add denser/adaptive switch points rather than log-interpolating discrete ranks.
- [medium] The claimed new-pair diagnostic actually evaluates all of G (lab/experiments/EXP-001-freq-ban/freq_ban.py:354-358)
  At the switch, `new_train_acc_before` evaluates the entire G set. Because roughly 72% of G is shared with F, this metric is dominated by already-seen pairs and does not implement the README's promised accuracy on new pairs. It can conceal pair memorization—the principal alternative explanation for apparent frequency retention.
  Recommendation: Compute and record accuracy separately on G\F, F\G, and F∩G, including their counts and hashes. Use the unseen G\F result as the pre-switch transfer diagnostic.
- [medium] The queue masks smoke and training failures (lab/experiments/EXP-020-data-switch/queue.sh:7-16)
  The wrapper exits only for codes 3 and 124. Ordinary Python failures such as assertion, validation, missing-file, or analyzer-relevant switch errors return other nonzero codes and are silently treated as success, so the mandatory smoke can fail while all expensive jobs continue. This behavior also conflates the trainer's exit-1 completed-run skip with genuine failures.
  Recommendation: Make an already-completed run return zero or a dedicated code, then stop the queue on every other nonzero status. After the smoke, automatically assert the switch event, hashes, step boundary, and F/G diagnostic subsets before launching the matrix.
