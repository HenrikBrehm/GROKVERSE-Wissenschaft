# Codex Adversarial Review

Target: branch diff against 9a3fdb3
Verdict: needs-attention

Do not ship: completed-run reuse and snapshot writes can silently produce missing, stale, or mixed artifacts; scale run IDs can collide; and lr scaling is wrong when combined with alternation.

Findings:
- [high] The fail-closed skip check does not verify the requested snapshots (lab/experiments/EXP-001-freq-ban/freq_ban.py:250-255)
  The check only confirms requested indices exist in `spectra_steps.npy`. A pre-snapshot run—or a run without `--spectra-at` that already recorded a regular step such as 250—passes even when `we_snapshots.npy` is absent or stale. It also discards requests above `steps_completed`, so an unmet request can pass vacuously. Because `--spectra-at` leaves `run_id` unchanged, the process exits successfully while required artifacts are unavailable.
  Recommendation: Before skipping, validate `spectra.npy`, both step arrays, and `we_snapshots.npy`: require matching lengths/shapes, snapshot step 0, and every requested reached step. Treat any requested step beyond the completed trajectory as an explicit failure rather than filtering it out.
- [high] Forced reruns can leave completed directories containing stale or partial snapshots (lab/experiments/EXP-001-freq-ban/freq_ban.py:377-384)
  Snapshot arrays are overwritten directly before the atomic JSON replacement. During `--force`, the previous completed `result.json` remains authoritative while these files are truncated and rewritten; interruption, disk-full, or write failure can therefore leave a completed directory pointing to mixed or corrupt artifacts. Even a successful forced rerun without `--spectra-at` leaves old snapshot files because the conditional write never removes them.
  Recommendation: Atomically mark the directory running before touching prior artifacts, write every array to a temporary generation and rename only after successful completion, delete optional snapshot files when not produced, and publish the completed manifest last with artifact checksums or generation-specific filenames.
- [high] Scale arguments can collide in run IDs or admit non-finite corrupting values (lab/experiments/EXP-001-freq-ban/freq_ban.py:227-234)
  The `:g` formatting rounds finite floats, so distinct interventions such as 1.0000001 and 1.0000002 both map to `_lrs1` (and likewise for `_wes1`); the second invocation can silently skip and reuse the first result. Separately, NaN and positive infinity pass the `<= 0` checks and can propagate invalid parameters or learning rates into a run that is still written as completed.
  Recommendation: Reject non-finite scales with `math.isfinite`, encode finite floats injectively using a canonical exact representation or parameter hash, and verify the requested scale against completed-result metadata before skipping.
- [medium] LR scaling is applied to G blocks during alternation (lab/experiments/EXP-001-freq-ban/freq_ban.py:402-405)
  `on_first` means only “before the permanent switch”; it does not reflect the currently active `trx`. With `--alternate-every`, the trainer changes to G after the first block, but every G block before `switch_step` still receives the scaled learning rate while `step <= 250`. This violates the stated first-train-set/F-only intervention and confounds combined runs.
  Recommendation: Either reject `--lr-scale` together with `--alternate-every`, or track the active split explicitly and apply the scale only while F is active.
