Findings:
- [high] The R reference and validity gate are circular and asymmetric (lab/experiments/EXP-041-imprint/analyze.py:93-101)
  `ex` is defined from pre-existing E targets, while `rx` is personalized from the observed pure-R endpoint. Because K_R is a subset of `rx`, `d(R) = -|K_R \ Ex| <= 0` after shared frequencies are removed; half of the validity rule is therefore guaranteed by construction, whereas E must empirically realize its targets. Filtering on `d(E) > 0 > d(R)` consequently selects E-successful seeds while almost automatically retaining R. Harmonic folding can also produce unequal set sizes—seed 22's Ex has nine unique frequencies—yet raw hit counts are not normalized. Negative and positive d therefore do not represent symmetric evidence, so an apparent E-to-R versus R-to-E asymmetry could be created by the measure itself.
  Recommendation: Define both references identically: either use split-derived sets for both arms or derive both from K_E and K_R using independent/cross-fitted controls. Equalize or normalize reference-set cardinality, and do not exclude seeds using asymmetric outcome-based validity criteria.
- [high] The analysis never verifies that the claimed prefix frequencies existed at the switch (lab/experiments/EXP-041-imprint/queue.sh:11-17)
  Pure controls are observed after 2000 total updates, while switched endpoints occur after 2050 or 2150 updates, and Rx labels a 50/150-step R prefix using the pure-R outcome at step 2000. No exact switch-time spectrum or endpoint-stability check is requested. A switched endpoint can therefore be called "R held" even if the prefix had not selected K_R at the switch, or if agreement arose from shared initialization or later spectral evolution. Equal post-switch exposure does not control total AdamW age, and E/R learning-speed differences can masquerade as directional imprint strength.
  Recommendation: Record spectra exactly at steps 50 and 150, report whether the prefix produced the claimed direction, and require or report endpoint stability. Add clock-matched pure controls at 2050/2150 alongside the exposure-matched 2000-step controls, or narrow the claim to the explicitly chosen estimand.
- [high] Two opposite one-sided tests do not control the advertised 0.05 error rate (lab/experiments/EXP-041-imprint/analyze.py:75-81)
  With five valid seeds, unanimity in either direction is declared significant because each one-sided tail is 1/32 = 0.03125. Since the code publishes either `gepraegt` or `ueberschrieben`, the per-endpoint probability of some decisive verdict under fair signs is 2/32 = 0.0625, already above 0.05. The same procedure is then applied to two primary endpoints without multiplicity correction. With six seeds it also has useful power only for 6/6; 5/6 is forced to `gemischt`.
  Recommendation: Choose one confirmatory direction and treat the opposite descriptively, or use an exact two-sided test with family-wise correction across P41a/P41b. Increase the seed count and derive MIN_SEEDS from the corrected decision threshold.
- [medium] The loader accepts incompatible completed runs despite claiming fail-closed behavior (lab/experiments/EXP-041-imprint/analyze.py:49-67)
  The loader checks status, seed, observed steps, and hashes, but not `max_steps`, `m`, condition/experiment identity, optimizer configuration, stop policy, top-level switch metadata, or that `final_top_m_freqs` contains exactly five unique in-range integers. Split-file run IDs omit `m` and step/configuration details, so a completed run produced with `--m 10` can occupy the same directory, be skipped by the queue, and then be accepted here; its ten frequencies silently change d. Configuration or schema drift can similarly mix incompatible runs.
  Recommendation: Validate a complete expected run manifest, including run_id, exp_id, condition, m=5, max_steps, stop policy, configuration/hyperparameters, switch_step and both switch hashes. Validate the exact frequency-list schema, and include a configuration hash in run IDs and skip decisions.
