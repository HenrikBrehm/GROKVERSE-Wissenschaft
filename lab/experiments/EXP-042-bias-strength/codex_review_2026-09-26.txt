Verdict: needs-attention

Do not ship: the experiment can produce a mechanistically false-positive H42 verdict, is not reproducible from a clean checkout, and overstates a coarse null result.

Findings:
- [high] The primary result cannot discriminate H42 from stronger erosion or a path-length clock (lab/experiments/EXP-042-bias-strength/README.md:14-30)
  Changing eps_G from 2 to 8 changes several causal variables simultaneously. The generated splits reduce F/G overlap from 2745–2795 pairs in EXP-020 to 2164–2217, while roughly doubling G target-power share. Consequently the fixed G phase contains about 50% more replacement examples and stronger G-aligned updates. Ordinary forgetting or an amplitude/Λ/path-length clock therefore predicts the same later crossing without H42's claimed head-start threshold. Acknowledging the confound does not make the registered “all later → H42 supported” verdict diagnostic.
  Recommendation: Before running, match or factorialize overlap and G endpoint/update strength, record amplitude/Λ/path length through the G phase, and preregister distinct quantitative predictions for H42 versus erosion/clock mechanisms.
- [high] The analysis depends on ignored, version-skewed EXP-020 raw data (lab/experiments/EXP-042-bias-strength/analyze.py:40-50)
  The monkeypatch redirects t=inf to EXP-020/raw, but that directory is gitignored and contains no tracked files; queue.sh explicitly does not regenerate these references. On a clean checkout the expensive queue can finish and every cell will still be incomplete at t=inf. On this checkout the four reused references were produced at four different commits, while the loader checks only split/test hashes and initialization checksum—not trainer revision, configuration, or library provenance—so incompatible historical results can be silently combined with new runs.
  Recommendation: Generate an only-F reference for every seed in the EXP-042 queue using the same code/environment, or require immutable versioned artifacts and fail closed unless trainer revision, full configuration, and library versions match.
- [medium] An interval-censored tie is incorrectly interpreted as no effect (lab/experiments/EXP-042-bias-strength/analyze.py:24-37)
  Both latent commitment times can move substantially within (25,50] and still be classified as “same”; for example, a shift from 26 to 49 steps is invisible to this grid. Nevertheless verdict() reports “Neigung ohne Einfluss auf den Zeitpunkt,” turning insufficient resolution into an absence-of-effect conclusion.
  Recommendation: Report this outcome only as “no shift detected at the registered grid resolution,” or add a denser paired grid and a preregistered equivalence margin capable of supporting a no-effect claim.
- [medium] The queue does not enforce the one-training-job invariant (lab/experiments/EXP-042-bias-strength/queue.sh:4-8)
  The queue claims one job at a time but merely invokes guarded_run.py sequentially. That guard enforces time limits but has no process lock, and this queue lacks the existing-job wait used by EXP-020. If another training or queue is already active, EXP-042 starts concurrently, violating the repository's one-job rule and risking resource contention, timeouts, and unusable multi-hour runs.
  Recommendation: Enforce an atomic global training lock in guarded_run.py, or add a fail-closed queue preflight that refuses to start while another guarded training process is active.
